Technical reference manual for the Always Bank website staging build. Designed to guide future updates, CMS management, and interest rate adjustments.

Project Overview

This technical guide covers the settings, script integration, and structures built on Webflow. It serves as a roadmap for content editors and developers managing the Always Bank website.

Layout & Styling Adjustments

Custom CSS patches have been injected into the project to guarantee pixel-perfect layout states across different viewport widths.

Typography Clipping Fix

To avoid text clipping on lower descenders (letters like 'g', 'p', 'y') within navbar buttons, the line height of the text block has been aligned:

.nav-link-text-2 {
  line-height: 1.3 !important;
}

Mobile Navbar Stacking

Webflow's native navigation components sometimes stretch layout blocks inline on tablet/mobile views. We forced block alignments to maintain neat vertical alignment of links:

@media screen and (max-width: 991px) {
  .link-block-3.w-inline-block {
    display: block !important;
    width: max-content !important;
    margin-left: auto !important;
    margin-right: auto !important;
  }
}

Dynamic Sitemap Engine

The HTML Sitemap page (/sitemap) uses a custom JavaScript engine that automatically pulls new URLs from the auto-generated sitemap.xml upon publishing. This guarantees that new pages appear instantly in the sitemap without manual maintenance.

How It Works

  1. Grabs the XML sitemap from the server root.
  2. Filters out utility paths (like /404, search, and category page templates).
  3. Classifies URLs under the correct columns based on slug keywords (e.g., placing savings under "Banking", loans under "Loans", factoring under "Factoring", etc.).
  4. Empties the design grid and renders a clean, balanced, 4-column column structure.
Designer Tip
If you want to edit the sitemap manually as standard text blocks inside Webflow Designer, you can simply delete the custom sitemap script from the Page Settings > Custom Code (Before tag).
View Complete Sitemap JavaScript Code

Paste this script in the Custom Code section of the Sitemap page settings in Webflow:

<script>
document.addEventListener("DOMContentLoaded", function() {
  const gridContainer = document.querySelector(".sm-grid");
  if (!gridContainer) return;

  function getTitleFromPath(path) {
    if (path === '/') return 'Home';
    const cleanPath = path.replace(/^\/|\/$/g, '');
    const overrides = {
      'savings': 'Savings',
      'basepoint': 'BasePoint',
      'traditionals-loans': 'Traditional Loans',
      'sba-loans': 'SBA Loans',
      'usda-loans': 'USDA Loans',
      'invoice-factoring': 'Invoice Factoring',
      'asset-based-lending': 'Asset-Based Lending',
      'about-us': 'About Us',
      'contact-us': 'Contact Us',
      'request-form': 'Request Form',
      'privacy-policy': 'Privacy Policy',
      'accessibility-statement': 'Accessibility Statement',
      'blog': 'Blog',
      'faqs': 'FAQs'
    };
    const pathKey = cleanPath.toLowerCase();
    if (overrides[pathKey]) return overrides[pathKey];
    return cleanPath.replace(/[\/\-_]/g, ' ').trim();
  }

  function getCategoryFromPath(path) {
    const cleanPath = path.replace(/^\/|\/$/g, '').toLowerCase();
    if (cleanPath === '') return 'Main';
    if (cleanPath.includes('basepoint')) return 'BasePoint';
    if (cleanPath.includes('factoring') || cleanPath.includes('lending')) return 'Factoring';
    if (cleanPath.includes('loan')) return 'Loans';
    if (cleanPath.includes('saving') || cleanPath.includes('checking')) return 'Banking';
    if (cleanPath.includes('about')) return 'About Us';
    if (cleanPath.includes('blog') || cleanPath.includes('faq')) return 'Resources';
    if (cleanPath.includes('contact') || cleanPath.includes('form')) return 'Contact';
    if (cleanPath.includes('policy') || cleanPath.includes('accessibility')) return 'Legal';
    return 'Others';
  }

  fetch('/sitemap.xml')
    .then(res => res.text())
    .then(str => new window.DOMParser().parseFromString(str, "text/xml"))
    .then(data => {
      const urls = Array.from(data.querySelectorAll("loc")).map(el => new URL(el.textContent.trim()).pathname);
      const filtered = urls.filter(p => !p.includes('/404') && !p.includes('/search') && !p.endsWith('.pdf'));

    });
});
</script>

Blog Structure & Maintenance

The Blog is built on a hybrid architecture combining Webflow CMS Collections with dynamic custom JavaScript plugins. This ensures clean pagination, category-specific filtering, and an automated related posts block without relying on resource-heavy external libraries.

A. Webflow CMS Database Schema

The Blog relies on two interconnected CMS collections. Understanding their fields and constraints is crucial for regular upkeep:

Show CMS Collections & Field Structures

1. Blog Categories Collection (categories)

Holds the category divisions. Adding a category here creates a new filter value.

  • Name: E.g., SBA & Loan Education. Used as display label.
  • Slug: Auto-generated URL string (e.g., sba-and-loan-education). Crucial: Used as the unique identifier by the filtering script.

2. Blog Posts Collection (blog-posts)

Holds individual articles. The table below lists critical fields to populate:

Field Name Type Description Client Guidelines
Name Plain Text Article main title Keep under 60 characters for best layout stacking.
Slug URL Slug Post URL path component Auto-generated by Webflow based on the title.
Category Reference Single reference to Category Mandatory. Links post to its filter and sidebar references.
Excerpt Plain Text 1-2 sentence preview text Appears on blog card grids. Limit to 150-160 characters.
Thumbnail Image Image Card grid preview photo Upload WebP format only. Dimensions: 800x600px, size < 80 KB.
Main Image Image Hero image at article top Upload WebP format only. Dimensions: 1200x800px, size < 150 KB.
Rich Text Body Rich Text Main reading content Format subheaders as H2/H3. Avoid H1 inside the body.
Read Time Plain Text Estimated reading time E.g., "5 min read". Displayed on cards.
SEO Title Page Title Search engines title override Auto-populates. Ensure it contains | Always.bank.
SEO Meta Description Meta Text Search engines snippet card Write an engaging 150-character summary of the post.

B. How the Custom Scripts Work

The Blog operations are powered by client-side Javascript scripts: blog-category-filter.js and blog-pagination.js. The execution flows as follows:

  • Page URL & Filter Binding: The script scans the category links for the attribute [data-blog-filter="slug"]. When clicked, it updates the address bar (e.g., /blog?category=slug) using the browser History API, then shows only items containing that category's slug in their hidden text block (.blog-item-category-slug).
  • Responsive Pagination: The script counts the active filtered items and divides them into pages. It renders 15 items per page on Desktop and 5 items per page on Mobile to minimize rendering load times. It injects page selectors in the .sectionpagination element and scrolls the page back up to #blog-posts-list on page click.
  • Dynamic Related Posts: On the template page (/blog-posts/*), the script reads the current page's category, fetches the main /blog list via a background HTTP request, extracts alternative posts sharing the same category (excluding the current page), and builds up to 3 recommendation links inside the sidebar (.blog-sidebar-list).

C. Maintenance & Publishing Checklists

Follow these step-by-step procedures to add content cleanly without disrupting site designs:

1. New Blog Post Checklist

  • Open Webflow Editor/Designer CMS panel and click Blog Posts.
  • Select + New Blog Post and fill in the text fields.
  • Select Category: You must select an active category from the dropdown to link your post.
  • Upload optimized WebP images (thumbnail and main header). *Do not upload raw PNG or JPG files!*
  • Fill out the SEO settings (Meta Title and Meta Description).
  • Save, preview, and click Publish.

2. Adding a New Category

If adding a new category block like "Financial Security":

  • Create the Category in the **Blog Categories** CMS collection and copy the auto-generated slug (e.g. financial-security).
  • In Webflow Designer, go to the /blog page and select the categories navigation menu.
  • Add or copy a Link block. In Link Settings (gear icon), add a Custom Attribute:
    Name: data-blog-filter
    Value: financial-security
  • Update the text of the button to "Financial Security", save, and publish the site.

3. Image Optimization Benchmarks

  • Format: WebP only.
  • Compression: Compress all images using TinyPNG before uploading.
  • Thumbnails size limit: < 80 KB (Dimensions: 800px width max).
  • Hero/Headers size limit: < 150 KB (Dimensions: 1200px width max).

FAQ Page Architecture

FAQs are structured using static categories pages (e.g., /faq-categories) and detailed detail pages for specific topics.

A. FAQ Breadcrumb Link Structure

The navigation breadcrumb on FAQ detail pages links back to the main categories. Webflow requires strict HTML rules for lists:

  • The breadcrumb list wrapper must only contain List Item elements.
  • Ensure the newly added "FAQs" intermediate category is defined as a list item (<li class="bc-item-2">) containing a text link pointing to /faq-categories.

B. Answer Accordion toggles

FAQs answers are packed inside accordion cards. Clicking on the top header (.accordion-top) triggers Webflow interactions that dynamically toggle the height of the answer content block (.accordion-bottom).

Accessibility & compliance

The website is optimized for WCAG accessibility guidelines to ensure screen-reader and keyboard compatibility.

A. Keyboard Focus States

Active focus outlines have been styled globally using custom CSS. Interactive elements (buttons, links, inputs) indicate their active focus with a border offset:

:focus-visible {
  outline: 2px solid #502BE5 !important;
  outline-offset: 3px !important;
}

B. Skip navigation link

A hidden "Skip to main content" link (.ab-skip-link) is injected at the start of the body to allow keyboard and screen-reader users to skip header nav blocks.

C. Cookies Modal

The cookie banner modal (.cookie-consent_card) features a custom script that blocks Google Tag Manager (GTM) tracker scripts until the user hits "Accept". It also traps keyboard focus when active to comply with ADA dialog parameters.

Webflow Editor vs. Webflow Designer Guide

To ensure long-term stability and prevent breaking layout structures, custom JavaScript, or style settings, it is highly recommended to follow this separation of access when managing the site.

A. Webflow Editor (Recommended for Client Content Management)

The Webflow Editor is a clean, visual-only interface that loads directly on top of the live website. It allows content managers to edit copy, update images, and manage CMS records safely without exposing the underlying HTML/CSS code or layout structures.

  • Best Used For:
    • Editing visible text blocks (e.g. modifying the APY rate in paragraph text).
    • Creating, editing, and publishing blog posts or categories.
    • Adding new FAQs or editing accordion answers.
    • Replacing thumbnail and body images.
  • How to Access the Editor:
    1. Open your browser and navigate to https://always-bank-8dd505.webflow.io/?edit (or the production canonical URL with ?edit appended).
    2. Log in using your client editor credentials.
    3. The page will load with a gray control bar at the bottom. Hover over any editable element (like a paragraph or image) and click the pencil icon to make updates directly on the page.
    4. To manage blog posts and categories, click the Collections tab in the bottom bar.
    5. Click Publish in the bottom bar to push your content changes live instantly.

Safety Advantage

The Editor makes it impossible to accidentally delete CSS styles, break layout structures, or damage custom scripts (like sitemap, blog filtering, and accessibility plugins).

B. Webflow Designer (For Structure, SEO, & Code Management)

The Webflow Designer is the full canvas and development interface. Changes here impact layout structure, responsive grids, custom scripts, page settings, and SEO configurations.

  • Required For:
    • Building new pages, landing templates, or deleting structures.
    • Modifying custom code blocks (such as the APY JSON-LD structured schema script in the Home/Savings settings, or sitemap script filters).
    • Adding or editing custom attributes (like data-blog-filter for manually built categories).
    • Changing CSS classes or styling parameters (e.g., adding line-height clipping fixes).

Warning

The client should delegate these changes to a developer or trained designer to prevent broken scripts or disrupted page layouts.
